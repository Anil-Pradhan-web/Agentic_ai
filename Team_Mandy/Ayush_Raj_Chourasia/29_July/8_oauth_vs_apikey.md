# API Keys vs. OAuth: Positives and Negatives

When building AI agents that need to authenticate with external services (like Google Drive, Twitter, or AWS), developers must choose between Static API Keys and Dynamic OAuth tokens. 

---

## 1. API Key (Static & Permanent)

An API Key is a long, static string (e.g., `sk-proj-12345...`) generated by a service to identify the caller.

### Positives (+)
1. **Simplicity:** Extremely easy to implement. You just paste it into an `.env` file and pass it in the `Authorization: Bearer` header.
2. **No Expiration:** They don't expire unless manually revoked, meaning a background agent won't suddenly crash because its session timed out.
3. **Ideal for Server-to-Server:** Perfect for backend autonomous agents querying a service (like an LLM provider) where there is no human user to log in.

### Negatives (-)
1. **High Security Risk:** If the key is leaked (e.g., accidentally pushed to GitHub), anyone can impersonate the agent and rack up massive bills or steal data.
2. **Coarse Permissions:** API keys often grant full admin access. It's difficult to scope an API key to "read-only" for a specific user.
3. **Difficult to Rotate:** Rotating a compromised key requires manually updating the server environment variables.

---

## 2. OAuth Key (Dynamic & Session-Based)

OAuth (Open Authorization) is a standard where an application redirects a user to log in, and receives a temporary Access Token and a Refresh Token in return.

### Positives (+)
1. **High Security:** Access tokens are short-lived (usually 1 hour). If an access token is stolen, the window of vulnerability is very small.
2. **Granular Scopes:** You can request very specific permissions (e.g., `calendar.read.only`). If the agent is compromised, it can't delete files.
3. **User-Delegated Access:** Allows an AI agent to act *on behalf* of a specific user. The agent accesses User A's data using User A's token, rather than a god-mode API key.

### Negatives (-)
1. **Complex Implementation:** Requires managing OAuth flows, redirect URIs, secure storage of Refresh Tokens, and handling token expiration logic.
2. **Friction for Autonomous Agents:** If a refresh token expires or gets revoked, the agent is completely blocked until a human intervenes and logs in again. This is bad for agents meant to run indefinitely in the background.
