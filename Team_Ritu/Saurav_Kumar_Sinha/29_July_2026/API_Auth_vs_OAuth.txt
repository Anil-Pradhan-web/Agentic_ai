# Task 2: 
Comparison of OAuth Keys (Dynamic & Session-Based) and API Keys (Static & Permanent)

Modern applications communicate with external services using authentication mechanisms to ensure secure access. Two of the most common authentication methods are OAuth and API Keys. While both are used to access APIs, they differ significantly in terms of security, user authentication, and usage scenarios.

# OAuth (Dynamic & Session-Based)

## OAuth is an authorization framework that allows users to grant applications limited access to their resources without sharing their passwords. Instead of using permanent credentials, OAuth issues temporary access tokens that expire after a certain period. These tokens can be refreshed securely using refresh tokens. OAuth is widely used by services such as Google, GitHub, Microsoft, Facebook, and LinkedIn for user login and secure authorization.

# Advantages of OAuth

High level of security through temporary access tokens.
Users do not share their passwords with third-party applications.
Fine-grained permission control (scopes).
Tokens can be revoked or refreshed when needed.
Suitable for applications requiring user authentication.
Disadvantages of OAuth
More complex to implement than API keys.
Requires multiple authentication steps.
Token management and refresh mechanisms increase development complexity.
Initial setup requires an authorization server.


# API Keys (Static & Permanent)

## An API Key is a unique string generated by an API provider that identifies an application. Unlike OAuth tokens, API keys are generally long-lived and remain valid until manually revoked or regenerated. API keys are commonly used for server-to-server communication and public APIs such as weather services, mapping APIs, and AI services.

# Advantages of API Keys

Simple and easy to implement.
Suitable for quick integration.
Low development complexity.
Works well for server-side applications.
Disadvantages of API Keys
Lower security compared to OAuth.
If exposed, unauthorized users can access the API.
No user identity or permission control.
Keys must be manually rotated if compromised.


# Conclusion

## OAuth and API Keys serve different purposes. OAuth is ideal for applications requiring secure user authentication and authorization, while API Keys are better suited for simple application authentication and server-to-server communication. For applications involving user accounts and sensitive data, OAuth is the preferred choice due to its stronger security and flexible permission management.
